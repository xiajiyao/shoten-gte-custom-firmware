# 验证记录与边界

## 使用者反馈

以下为单一使用者在开发过程中的反馈摘要，不是受控实验或厂商测试。设备为 GTE V01.02、A7 IV / ILCE-7M4 6.02，主要镜头为 Planar G35/2。

| 版本 | 反馈 | 能支持的结论 |
| --- | --- | --- |
| 0.51 | 刷入成功，机身显示 .51；随后反馈近距离 AF-C 反复拉动及松开快门后回无穷远 | 有实际刷入记录，同时存在控制问题 |
| 0.52 | “测试成功” | 修复版本在该组合上获得可用反馈；没有完整场景统计 |
| 0.53 | 对焦速度有提升，视频会切换目标，按 REC 后缓慢合焦 | 有主观性能改善及基本视频对焦反馈；没有计时数据 |
| 0.54 | 不确定速度有没有进一步提升 | 不能宣称其实际速度继续提高 |
| 当前 0.55 | 使用者表示目前版本可以，要求整理并发布 | 有限的接受反馈；没有新增全镜头、全区域、温升或量化测速记录 |

没有收到其他五个镜头预设的实机验证记录。全画面可用率、边缘准确率、低光、不同机身和不同录像格式尚未完成系统验证。

## CPU 仿真

`src/verify.py` 使用 Unicorn 执行编译后的 ARM 指令，加载确切原版和历史镜像，检查 8208 个断言。`release/v0.55-exp/verification.json` 是本次复现输出。

覆盖项目包括：

- 六个预设的早期握手、镜头身份、焦距、能力位、光学文件结构、校验和及分包。
- 长短回复间 DMA 指针切换与原版发送流程；不模拟真实 DMA 外设时序。
- 移动模式、目标限位、同向更新、换向、显式 Stop 和真实停机函数的写寄存器行为。
- 0.51 已知启动、停机和当前位置回报缺陷的回归复现。
- 实际 PID 输出、驱动方向、渐退、目标/边界保护条件及随机化组合。
- 0.55 稳定到位、穿越目标、漂移、抖动、目标替换、观测不足、间隔中断、计时回绕及重置等路径。

模拟器通过修改寄存器和内存给出位置及时间输入，不模拟镜头机械系统。程序看到的“到达目标”不等于画面已经光学合焦。

## 数字应该怎样理解

| 数字 | 含义 | 不能推导的结论 |
| --- | --- | --- |
| 5040 → 7056 | 条件满足时的输出限幅上限增加 40% | 马达或总 AF 速度提高 40% |
| 名义 60% → 84% | 依原版定时器和 PWM 配置推算的最高运行占空比 | 已测得电流、转速、功率或温度 |
| 10000 → 1200 个节拍 | 固定位置稳定到位的同一仿真样例中，旧/新代码停机时点 | 每次 AF 都能减少相同等待 |
| 名义 12ms | 新路径最小观测时间；还要求至少 8 次分开观测 | 总 AF 只需 12ms |
| 8208 项 PASS | 本验证程序的断言全部通过 | 8208 次真实镜头对焦成功 |

名义时基约 10µs/节拍，依据本镜像定时器初始化推算，没有示波器校验。[optimization_review.json](optimization_review.json)保留本轮瓶颈分析数据。

## 尚待实测

光学资料使用 ZEISS 公开规格、未实测的 4.5mm 行程假设和 EA9 的经验比例；边缘行数据采用平坦模型，没有逐镜头标定。AF-S Scan 和变焦位置检测未实现，视频专用功能暂停开发。实际惯性、摩擦、位置反馈噪声、供电、电流、温升、长时间运行和故障恢复都需要真实设备验证。

若反馈速度，建议在相同机身、镜头、光圈、光线、目标与对焦设置下，两个版本各做多次近远转换，并同时记录焦点清晰度和耗时。中心及边缘位置分开记录，不把主观体感写成精确百分比。
